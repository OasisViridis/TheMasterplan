# v5.1.2 发布说明

发布状态以 [GitHub Release](https://github.com/OasisViridis/TheMasterplan/releases/tag/v5.1.2) 与 `v5.1.2` 不可变 Tag 为准；源码版本声明不证明发布已完成。

## 这次解决了什么

多人使用同一工作流时，可以通过 GitHub 现有功能分工、认领与交接。执行 Issue 由一位 Assignee 认领，各任务独立分支与 PR；父 Issue 的协调人维护拆分、依赖与整体验收。准备状态沿用 Matt 的标签，阻塞使用 GitHub 原生关系，上游合并且约定结果验收后，下游才能开始。重复认领暂停写入并保留修改，任务释放先停止作业、记录实际状态，再清空指派。

技术审阅可以由未参与实现的另一 Agent 会话完成；人类负责批准 PR 和决定合并。删除额外的“非作者人类”资格限制，实际平台要求的 review、CI、权限与保护规则仍须满足。技术报告和结构校验不能代替人类审阅决定或执行授权。

完整协作变更见 [PR #107](https://github.com/OasisViridis/TheMasterplan/pull/107) 与 [Issue #106](https://github.com/OasisViridis/TheMasterplan/issues/106)。本次同时同步分发版本和中央 Actions 调用示例。

## 升级时要注意

- 从 `v5.1.1` 更新会替换受管 Core 规则；本地修改和同名未登记文件仍按既有停止条件处理，不覆盖项目定制。
- Issue/PR 模板、正文 validator 和团队参考文档不属于受管升级文件，采用项目须按需显式同步。`Human approval` 对历史记录可选；CI 只检查结构，不验证真实批准、身份或权限。
- 不新增 CLI 命令，不改变 State schema、Actions 公共输入、权限或 required check 名称。
- 已发布版本和冻结的 `v1` 保持现状，不移动或覆盖。发布采用 tag-only 顺序：annotated Tag → 固定 Tag 消费者 smoke → GitHub Release（`--verify-tag`）→ 远端核验。

## 验证范围与限制

仓库回归覆盖版本一致性、协作正文兼容和采用/升级契约；发布还需验证真实源下载与隔离的 Git/jj Profile 消费者采用。它们不代表消费者 GitHub Actions 或真实多成员平台演练已通过，这些行为未验证。继承的主动技能求助五类 Agent 行为场景仍未验证，详见 [此前验收记录](../validation/issue-103.md)。

固定 Tag smoke 未通过时不得创建 Release；候选、目标或远端状态变化时停止并重新核验。发布说明、Agent 审阅或 CI 都不替代所需人类授权。
