# v5.1.1 发布说明

这是本次发布准备的中文说明。发布状态以 [GitHub Releases](https://github.com/OasisSaber/TheMasterplan/releases) 与 `v5.1.1` 不可变 Tag 为准；这份文件或版本清单本身不证明版本已发布。

## 这次解决了什么

- **Agent 遇到知识或方法缺口时会主动求助，而不是先猜。** 采用项目新增通用的主动技能协作契约：预见缺口或关键不确定性时立即路由到适合且已可用的方法技能（Matt Pocock 方法技能优先，适合程度与可用性是前提），缺失、不可读或不适合时回退到现有技能或工具继续推进；用户自己调用的完整流程仍只推荐、由用户启动，不会被一次求助顺手带起来。求助过程不自动安装或更新技能，也不改变授权、完成合同与外部治理退让要求。见 [PR #104](https://github.com/OasisSaber/TheMasterplan/pull/104)（Issue [#103](https://github.com/OasisSaber/TheMasterplan/issues/103)）。

为了让采用项目不必预读整套规则，Core 只保留一条简短触发规则；详细的选择、调用边界、缺失回退和首批示例（调研 / 诊断 / 设计 / 审阅 / 测试）放在 `core/skill-collaboration.md`，随采用包分发，由源仓库 Router 与采用项目受管 Router 提供相同的按需入口。

## 升级时要注意

1. `v5.1.1` 新增一个受管必需文件 `core/skill-collaboration.md`（`managed-replace`、必需）。升级计划会把它列为 `ADD`；批准并应用后安装并登记，受管 Router 区块之外的项目内容保持完整。
2. 目标路径已有同名未登记文件、或已登记文件被本地修改时，更新沿用既有停止条件，不会覆盖你的内容；先诊断、备份，再取得明确的恢复方案。
3. 登记后缺失或漂移由现有 `inspect` / `verify` / `doctor` 诊断，不自动重建被删改的登记。
4. 历史版本的最低 Core/Profile 文件集合保持不变，不因新参考把原本有效的旧安装判为损坏。
5. `v5.1.0`、`v5.0.0` 与冻结的 `v1` 都保持原指向，不移动、不覆盖；已有消费者不会自动收到这些变更。
6. 本次不新增 CLI 命令，不修改 State schema，也不修改中央 Actions 公共输入、权限与 required check 名称。

完整操作见 [更新指南](../client-update-flow.md)、[Actions 接口](../actions-interface.md) 和 [版本通道](../release-channels.md)。

## 已知限制

- **五类隔离 Agent 行为场景尚未验证。** 本候选附带的 [`docs/validation/issue-103.md`](../validation/issue-103.md) 把主动求助、简单任务、缺失回退、完整流程推荐与外部治理退让五个场景全部记为「未验证」：启动宿主 CLI 做行为演练时被自动审批审查拦下（任务与技能内容会传输到外部模型 provider，需先对该数据传输取得明确授权）。当时没有用模拟或静态检查顶替这些验收。因此本版本验证的是规则、分发与采用/升级回归，不是模型行为的实测结论。
- 真实采用与升级覆盖本机本地消费者与临时项目，不是生产采用验收，也不代表消费者 GitHub Actions 运行；宿主原生技能调用未验证。
- 独立代理审阅、CI 和结构校验不替代真实人类审阅、项目权限或发布批准。

## 发布执行前的门

先合并并验证发布准备 PR，固定最新 main 的完整候选 SHA，核验版本和 Release Notes，完成独立消费者检查和所需人类审阅。人类一次批准完整发布事务后，按协议连续执行：创建并推送 annotated Tag → 真实固定 Tag 消费者 smoke → 创建 GitHub Release（`--verify-tag`）→ 远端对齐验证。

固定 Tag smoke 未通过时不得创建 Release；候选、目标或结果变化时停止并重新审核。不要把发布准备或本说明的存在当作发布完成。
