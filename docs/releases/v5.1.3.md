# v5.1.3 发布说明

发布状态以 [GitHub Release](https://github.com/OasisViridis/TheMasterplan/releases/tag/v5.1.3) 与 `v5.1.3` 不可变 Tag 为准；源码版本声明不证明发布已完成。

## 这次解决了什么

采纳项目安装的是受管 Core 文件、所选 Profile 和 `AGENTS.md` 受管区块，没有上游仓库自带的完整文档树。`core/workflow.md` 按名字引用根部 `AGENTS.md` 的「Completion Contract」，受管区块却只有正文、没有这个标题；`core/policy.md` 又用 jj 的 bookmark 术语描述通用清理规则，只装 Git Profile 的采纳项目照着做没有对应动作。这两类缺陷在本仓库内都测不出来，只在采纳项目里暴露。

本次在受管区块补上 `## Completion Contract` 标题，并把 `core/policy.md` 的 profile 与 jj/bookmark 措辞改为中立表述：清理对象写作「本地同名任务引用（Git 分支或 jj bookmark）」，dry-run 同时给出 `git push --dry-run --delete` 与 `jj git push --deleted --dry-run`。新增契约测试会真实 adopt 一次（git、jj 各一遍），断言采纳树中的 Completion Contract 可解析、policy 不再点名未安装的 Profile。

变更见 [PR #119](https://github.com/OasisViridis/TheMasterplan/pull/119)。本次同时把源码版本、分发 manifest、README 与中央 Actions 调用示例对齐到 `v5.1.3`。

## 升级时要注意

- 从 `v5.1.2` 更新会替换受管 Core 规则，并重写 `AGENTS.md` 受管区块（新增 Completion Contract 标题）；项目自己维护的项目事实区块不受影响。
- 受管文件不允许本地直接修改；`themasterplan verify` 仍按受管 hash 判定，发现 `LOCAL_MODIFIED` 时按既有停止条件处理，不覆盖项目定制。
- 不新增 CLI 命令，不改变 State schema、Actions 公共输入、权限或 required check 名称，也不推进冻结的 `v1`。
- 已发布版本和 `v1` 保持现状，不移动或覆盖。发布采用 tag-only 顺序：annotated Tag → 固定 Tag 消费者 smoke → GitHub Release（`--verify-tag`）→ 远端核验。

## 验证范围与限制

仓库回归覆盖受管文档引用解析、采用/升级契约与版本一致性；本地权威入口 `scripts/check.sh` 在 Git for Windows Bash 下通过。消费者仓库的真实 update/verify、GitHub Actions 运行与多平台行为未验证；本发布说明、Agent 审阅或 CI 结果都不替代所需的人类授权。
