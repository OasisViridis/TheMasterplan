# v5.1.5 发布说明

发布状态以 [GitHub Release](https://github.com/OasisViridis/TheMasterplan/releases/tag/v5.1.5) 与 `v5.1.5` 不可变 Tag 为准；源码版本声明不证明发布已完成。

## 这次改了什么

v5.1.4 之后合入两处协议修复：

- 歧义先问（[PR #124](https://github.com/OasisViridis/TheMasterplan/pull/124)）：协议术语、授权门类或验收口径有两种合理解释时，先列两种解释让人类选，不自行定义、不扩大或缩小人类门禁；歧义影响执行时停在受影响的动作，其余安全工作照常继续。`core/workflow.md`、`AGENTS.md`、两个 SKILL 入口与 consumer managed block 同步；新增 `scripts/test_workflow_contract.py` 把入口规则做成契约测试。
- 技能调用授权（[PR #125](https://github.com/OasisViridis/TheMasterplan/pull/125)）：用户当次主动发起执行的技能或命令，按其说明把当次内容发给指定接收方时，调用本身构成该次数据外发授权，不再重复索要，也不自行删改内容规避；内容范围以当次要求为准，不自行删改只针对规避门禁，隐私、合规、安全约束仍优先；接收方以技能说明为准，说明缺失或与点名不符时先问；Agent 自行调用不构成授权。`core/policy.md` §1 新增规则，§1.2 写明凭据边界与例外（预先配置、由用户批准的认证机制）。

## 升级时要注意

- 从 v5.1.4 更新会替换受管 Core 规则（`core/workflow.md`、`core/policy.md`）并重写 `AGENTS.md` 受管区块；采纳项目自己维护的项目事实区块不受影响。
- 数据外发门禁的行为变了：用户主动调用的技能或命令不再触发二次授权；只在对话里提到命令名、Agent 自行调用、接收方说明缺失或与点名不符时仍然停止并问人。
- 版本与调用面对齐到 `v5.1.5`：`distribution/manifest.json`、README、中央 Actions 示例与 consumer 模板统一写 `@v5.1.5` 与 `policy-ref: v5.1.5`。不新增 Actions 输入，不改 required check 名称、State schema 或权限，不推进冻结的 `v1`。
- 已发布版本和 `v1` 保持现状，不移动或覆盖。发布采用 tag-only 顺序：annotated Tag → 固定 Tag 消费者 smoke → GitHub Release（`--verify-tag`）→ 远端核验。

## 验证范围与限制

- 仓库回归：`bash scripts/check.sh` 在 Git for Windows Bash 下通过（278 个用例、7 个跳过）；GitHub Actions 的 PR 检查与 `main` 检查通过。
- 未验证：消费者仓库的真实 `update` / `verify` 运行、固定 Tag 消费者 smoke、多平台采用演练。消费者 smoke 仓库不可达时，本轮不执行固定 Tag smoke；这些项目不因为本说明、Agent 审阅或 CI 结果而被视为已完成，需要时按采用指南补做。
- 本发布说明不替代所需的人类授权；发布事务按 `core/policy.md` §2 与 `docs/release-channels.md` 执行。
