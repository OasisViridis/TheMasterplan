# 区分日常凭据与获批事务的执行权限

2026-10-12 的全流程审阅中，人类选择日常凭据保持低权限，获批的合并/发布使用
单独授予的受限执行凭据。这样同时保留人类决定权和 Agent 执行已批准事务的责任，
避免把“Agent 无权自主发布”写成“Agent 永远不能执行发布”。

审核必须列明预期权限切换、精确目标与动作；实际平台权限、保护门与人类授权
分别核验。审核内的预期切换不导致逐步重复批准，审核外的权限变化仍停止。
不共享身份，不提交凭据，不授予 admin，不自动降低保护规则。

放弃“始终由人类手工操作”作为默认路径，因为它把已授权的执行工作重新交给
人类；也不采用日常凭据长期持有全部高权限。实际凭据机制由采用项目按平台能力
配置，本决定不要求安装新的凭据服务。

2026-10-12，人类在定稿会话以“定稿”接受本决定；定稿时 Core 与服务器权限尚未变更。
本次实施候选已更新 Core 与相关文档；尚未合入或发布，也未改变实际服务器权限。
实施范围与验收见[全流程修改计划](../workflow-audit-and-change-plan.md)。
